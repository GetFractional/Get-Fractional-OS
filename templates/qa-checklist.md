# QA Checklist — Creative Sprint Delivery

> Used by Matt before every client delivery (Day 10 draft and Day 14 final).
> Every item must pass before sending the kit to the client.
> Store completion status in Airtable: Sprints table, QA Status field.

---

### 1. BRIEF AND STRATEGY

- [ ] ICP brief is complete (1-2 pages, not bullet points)
- [ ] ICP matches intake form responses (cross-reference)
- [ ] Objection map has 5-7 objections with rebuttal angles
- [ ] Objections are sourced from URL analysis and intake data (not generic)
- [ ] 3-5 ad angles are distinct (not variations of the same angle)
- [ ] Each angle has a clear "why this works" explanation

### 2. HOOKS

- [ ] 15-25 hooks delivered (count: ___)
- [ ] Hooks are distributed across all angles (not clustered on one)
- [ ] No two hooks use the same structure/template
- [ ] Each hook is specific to this client's product (not generic)
- [ ] Hooks are appropriate for the client's brand voice
- [ ] At least 3 different hook types represented (pain, proof, objection, insight, specificity, before/after, social proof)

### 3. AD CONCEPTS

- [ ] 10-20 ad concepts delivered (count: ___)
- [ ] Each concept includes: headline, body copy, creative direction
- [ ] Concepts span multiple ad formats (static, video, carousel noted)
- [ ] Visual direction is specific enough for a designer to execute
- [ ] No concept contradicts the ICP brief
- [ ] Concepts reference specific product details (not generic copy)

### 4. LANDING PAGE COPY KIT

- [ ] Headline stack included (H1, H2, supporting subheads)
- [ ] Section structure mapped out (hero, problem, solution, proof, CTA)
- [ ] CTA copy is written (not placeholder)
- [ ] Objection handling is integrated into LP structure
- [ ] Social proof placement is specified
- [ ] LP copy is consistent with ad angles (the story connects)

### 5. TESTING PLAN

- [ ] Naming convention document included
- [ ] Test matrix specifies what to test first, second, third
- [ ] Each test has a clear hypothesis
- [ ] Success criteria are defined (what "good" looks like)
- [ ] Plan is realistic for client's budget and scale
- [ ] Media buyer or internal team can execute from this document alone

### 6. CONSISTENCY AND QUALITY

- [ ] Brand voice is consistent across all deliverables
- [ ] No spelling or grammar errors
- [ ] No placeholder text (all {{brackets}} filled in)
- [ ] File naming is clean and organized
- [ ] All deliverables reference the same ICP (no contradictions)
- [ ] Formatting is professional and easy to scan

### 7. DELIVERY PACKAGE

- [ ] All deliverables compiled in one organized document or folder
- [ ] Table of contents or summary page included
- [ ] Delivery email/message drafted with:
  - [ ] Summary of what's included
  - [ ] Next steps (review timeline, feedback instructions)
  - [ ] Link to Revision Policy
  - [ ] Feedback deadline (48 hours)

---

## POST-DELIVERY

- [ ] Delivery confirmation sent to client
- [ ] Airtable Sprint record updated (status: Delivered / Final Delivered)
- [ ] Calendar reminder set for 48-hour feedback deadline
- [ ] Proof capture notes saved (for case study use):
  - Deliverable counts: ___
  - Timeline adherence: On time / Delayed by ___
  - Client reaction (if noted): ___

---

## QUALITY GATE

**Pass:** All items checked → proceed with delivery.
**Fail:** Any unchecked item → fix before sending. No partial deliveries.

If a section has structural issues (not just minor fixes), delay delivery and notify the client with a revised timeline. A late delivery is better than a weak one.
